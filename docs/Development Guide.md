# Career Gap Navigator — Development and Replication Guide

This guide explains the **method of development**, not personal details of any
candidate. Share it alongside the actual Skill or standalone prompt so others
can design their own evidence-based AI workflows.

## Seven reproducible design steps

1. **Define the real user decision.** What job, funding or development decision
   should improve, and what must the tool never claim to know?
2. **Establish minimum intake.** Make CV, user-chosen direction, location/remote
   scope and target level essential; keep budget/course preferences optional.
   Never select the goal from examples or the CV without user confirmation.
3. **Specify source rules.** Only actual readable job postings or expressly
   requested opportunity calls can justify requirements. Keep types distinct:
   employer job criteria, formal programme eligibility and competitive
   selection factors need different treatment.
4. **Define evidence standards.** Separate exact knowledge, completed activity,
   accountable professional operation, and missing/adjacent evidence. Specify
   decision thresholds for the six labels; silence is not proof of deficiency.
5. **Build interaction gates.** Stage 1 asks 3–5 questions, each testing one
   coherent fact, then stops; Stage 2 reads real answers and carefully updates
   each R-ID, including reasons when a label remains unchanged.
6. **Convert findings to useful action.** At most three priorities and
   realistic 30/60/90-day outcomes. Search real courses only for justified
   learning needs, distinguish enrolment status from general catalogues, and
   favour lower-cost practical alternatives where suitable.
7. **Test limitations explicitly.** Test input omission, missing browsing,
   misunderstood yes/no responses, candidate diversity, new opportunity types,
   multilingual depth, and privacy. Use separate fresh runs and preserve raw
   outputs. Refine the minimum set of rules causing errors.

## Keep evidence sources separate

| External source | Candidate CV | Participant conversation |
|---|---|---|
| Actual opportunity criteria, source, checked date/status | Completed activity, precise knowledge, employment/learning evidence | New information labelled `SELF-REPORTED` until corroborated |

## Anonymous historical learning

In a limited **single-candidate / three-CV** illustrative comparison, an initial
classification set agreed on **14 of 18** requirements, while four varied. After
clarifying evidence rules, the same 18 fixed requirements agreed across all
three analyses. This is classification **consistency**, not validated accuracy,
representative market data or proof of real-world career impact. CV content
changed as well as emphasis, and some example job sources were historical.

## What is still unvalidated

The full workflow including real opportunity discovery, grants/fellowships,
question coherence, partial-answer interpretation, realistic courses,
multilingual parity and quality of development plans needs fresh diverse-user
and source-grounded review. Publication on GitHub does not validate behavior.

## Use this framework to build an unrelated Skill

```text
PURPOSE: State the user decision and boundaries.
MINIMUM INTAKE: Collect only decisive fields; ask and wait when missing.
SOURCES: Define authentic external sources, dates, status and mandatory criteria.
CLASSIFICATION: Set evidence thresholds, precedence and uncertainty labels.
STAGE 1: Evidence audit + limited coherent questions; STOP.
STAGE 2: Interpret exact answers, log changes and retentions, preserve scope.
GUIDANCE: Prioritised practice, verified resources, measurable roadmap.
QUALITY: Negative cases, multilingual parity, privacy, practical usability.
DEPLOYMENT: Package instructions as a Skill and a standalone prompt.
```

## Ethical publication

Publish only general rules and synthetic or anonymised examples. Never commit
actual CVs, names, addresses, raw participant replies, research-grant documents,
confidential client or employer details, or files from a controlled study.
Request consent for any real participant testing. The project is distributed
under the [MIT License](../LICENSE); retain the licence notice in copies.
